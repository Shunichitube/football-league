## 重要方針

```txt
ロビー以降のUIは、原則としてシングルプレイ準拠にする。
マルチ専用UIを新規に作り直さない。
マルチ側で追加するのは、フェーズ進行管理・完了状態表示・未完了クラブ表示・次フェーズへ進むための同期ボタンに限定する。
```

つまり、各フェーズの中身は既存のシングルプレイ画面・既存コンポーネントを使う。
マルチプレイ独自の画面は、ルーム管理と同期状態の表示に留める。

この方針なら、ドラフト・競売も自然に組み込める。
既存のドラフト画面・競売画面の上に、入力済み/未入力クラブ表示とフェーズ確定ボタンだけを重ねる。

## フェーズ進行方針

```txt
lobby
  参加クラブが準備完了する
  全員準備完了後、ホストがゲーム開始

team-setup
  シングルプレイ準拠の編成・戦術画面を使う
  マルチ側では完了状態と未完了クラブを表示する
  各クラブが完了ボタンを押す
  全員完了したら次フェーズへ進める

season-ready
  全員完了済み
  ホストがシーズン一括シミュレーションを実行する

season-result
  シングルプレイ準拠の結果表示へ寄せる
  マルチ側では共有結果と確認状態だけを管理する
```

## ドラフト・競売の組み込み方針

ロビー以降をシングルプレイ準拠にするため、ドラフト・競売も新規UIでは作らない。
既存のシングルプレイ画面を使い、マルチ側では入力状態と確定処理だけを管理する。

### ドラフト

```txt
draft
  既存のドラフト候補表示を使う
  各クラブが指名候補を選ぶ
  マルチ側で「指名済み / 未指名」を管理する
  全クラブが指名したら確定
  競合があれば抽選
  外れたクラブだけ再指名待ち
  全クラブの指名処理が終わったら次巡へ進む
```

追加する同期表示は以下だけにする。

```txt
・指名済みクラブ
・未指名クラブ
・全員指名後に確定するボタン/自動確定
・外れ指名中のクラブ表示
```

### 競売

```txt
auction
  既存の競売選手表示を使う
  各クラブが入札額または見送りを入力する
  マルチ側で「入力済み / 未入力」を管理する
  全クラブが入力したら開札
  最高額クラブが獲得
  同額なら抽選
  次の競売選手へ進む
```

追加する同期表示は以下だけにする。

```txt
・入札済みクラブ
・未入力クラブ
・全員入力後に開札するボタン/自動開札
・落札結果確認
・次の選手へ進むボタン
```

- ルーム作成
- ルーム参加
- クラブチーム名入力
- 参加順のクラブ枠割り当て
- CPUクラブ名は押し出し式で `COM1` / `COM2` / `COM3` ...
- シングルプレイ準拠UIで編成と戦術を送信
- 各フェーズの作業完了表示

- 全員完了後のフェーズ進行
- ホストがシーズン一括実行
- 結果共有

## 初期MVPではやらないこと

- 手動クラブ選択
- ドラフトのマルチ化
- オークションのマルチ化
- 育成のマルチ化
- 契約更新のマルチ化
- 放出のマルチ化
- 試合イベントログ共有
- D1保存
- WebSocket同期

## 注意

マルチプレイ化では、既存の `app.js` をいきなり大改修しない。

まずはサーバー側のルーム状態とAPIを別軸で作り、既存シングルプレイの計算ロジックを壊さず利用できる形を探る。

今回追加したWorkerとフロント画面はまだ実行確認前。Cloudflare上での `wrangler dev` / デプロイ確認は別途必要。

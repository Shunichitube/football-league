# FOOTBALL LEAGUE 追加改修仕様書 v0.5

— 選手情報・成長個性・CPU運営・シーズン進行改善 —

## 0. この文書の位置づけ

この文書は、既存のFOOTBALL LEAGUE実装に対する追加・修正仕様である。

既存の `GAME_SPEC.md` / `UI_SPEC.md` を破棄せず、本書の内容を優先して差分反映する。

目的：

- 選手の能力を把握しやすくする
- 選手ごとの個性を強くする
- ドラフト/競売の判断材料を増やす
- スカウトコメントを意味ある情報にする
- CPUクラブも人間クラブと同様に運営させる
- 10シーズン通して自然な世代交代が起きる状態にする

## 1. 選手能力の表示を強化

編成、ドラフト、競売、育成、契約、選手詳細、シーズン結果、個人成績では、所属選手および候補選手の能力をランク表示で必ず確認できるようにする。

表示能力は、シュート、走力、守備、ドリブル、パス、GK（GKのみ）。内部数値は引き続き非表示。

## 2. 所属選手確認ボタン

ドラフト中と競売中に「所属選手を見る」ボタンを常設し、画面遷移せずモーダルまたはサイドパネルで表示する。

表示内容：名前、年齢、ポジション、総合、シュート、走力、守備、ドリブル、パス、GK、特殊能力、契約残年数。GK / DF / MF / FWのポジション別人数も表示する。

## 3. 特殊能力の出現確認と表示修正

市場選手の特殊能力は候補生成時に、特殊能力なし60%、特殊能力あり40%の初期確率で付与する。特殊能力持ちには、すべての主要な選手カード上で `★ 特能名` を表示し、詳細画面では説明文も表示する。実際には生成されているがUIで見えない状態を禁止する。

## 4. 特殊能力の種類を正本仕様まで復元

- GK：ショットストッパー、ビッグセーバー、ロングレンジキラー、反応型、安定感、守護神
- DF：ボールハンター、カバーリング、パスカット、カウンター起点、ビルドアップ、最終防衛線
- MF：スピードスター、ドリブラー、チャンスメイカー、カットイン、ハードワーカー、万能型
- FW：フィニッシャー、ミドルシューター、ポストプレーヤー、個人技、勝負強さ、エース

## 5. hiddenGrowthを能力別へ変更

単一値の `hiddenGrowth` を廃止し、各能力ごとの成長傾向を持たせる。

```js
hiddenGrowth = {
  shoot: 0.82,
  speed: 1.18,
  defense: 0.94,
  dribble: 1.31,
  pass: 1.07,
  gk: 0.88
}
```

フィールド選手のgkは省略可能。初期選手は各能力0.55〜0.75程度、通常選手は各能力0.70〜1.30程度。

## 6. 成長処理修正

成長式では対象能力の `hiddenGrowth` を使う。同じ選手でも「走力は伸びるが守備は伸びにくい」などの個性を作る。

## 7. スカウトコメント全面改修

ポジション＋現在ランク中心のコメントを廃止する。現在能力、年齢、`hiddenGrowth` の傾向、特殊能力から生成する。ただし `hiddenGrowth` の内部値は直接表示せず、コメントはヒントのみにする。

## 8. 能力別スカウトコメント

- シュート成長：「得点感覚にはまだ伸びしろがありそうだ」「シュート技術は今後さらに伸びそうだ」
- 走力成長：「身体能力はこれからさらに伸びそうだ」「スピード面には成長の余地を感じる」
- 守備成長：「守備面は経験とともに伸びていきそうだ」「対人守備には将来性を感じる」
- ドリブル成長：「ボールを持った時の伸びしろを感じる」「ドリブル技術はまだ伸びそうだ」
- パス成長：「配球面にはまだ成長の余地がある」「パスセンスは今後さらに磨かれそうだ」
- GK成長：「GKとしてまだ伸びる余地がありそうだ」「反応やセービングはさらに良くなりそうだ」

## 9. 総合成長タイプコメント

複数能力の `hiddenGrowth` が高い場合は、低確率で「非常に高い成長性を感じる」「粗削りだが、大きく化ける可能性がある」「天才肌かもしれない」のレアコメントを追加する。

## 10. 成長コメントは確定情報にしない

「確実に伸びる」「必ずAになる」「成長率1.28」などは禁止し、必ず曖昧なスカウト表現にする。

## 11. 名前生成の多様化

日本人の苗字を150種以上、名前を100種以上へ増加する。IDベースの固定組み合わせを廃止し、seeded randomで独立抽選する。同一リーグ内で同姓同名が発生しにくいようにする。

## 12. Overall計算をポジション別に修正

5能力単純平均を廃止する。

- DF：守備35%、パス25%、走力20%、ドリブル10%、シュート10%
- MF：走力25%、ドリブル25%、パス20%、シュート20%、守備10%
- FW：シュート35%、ドリブル25%、パス15%、走力15%、守備10%
- GK：GK能力中心

## 13. CPUスタメン自動更新

CPUがドラフト・競売で選手を獲得した後、初期5人を固定で使い続けない。毎シーズン開始前にロスター全体からGK 1 / DF 1 / MF 2 / FW 1を、適性補正後の内部Overallを基準に再選出する。

## 14. CPU戦術自動設定

CPUクラブは毎シーズン、スタメン能力から戦術を自動決定する。パスが高い場合はポゼッション、ドリブルが高い場合はドリブル、走力が高い場合はカウンター、差が小さい場合はバランス。特殊能力との相性も軽く加味する。

## 15. CPUも育成対象を選択

CPU5クラブも毎年、若さ、成長余地、将来主力候補、現在ロスターでの重要性から育成対象2人を選ぶ。CPUは `hiddenGrowth` 自体を直接読まず、公開情報＋年齢＋内部ロジックで評価する。成長処理では `hiddenGrowth` を使用してよい。

## 16. CPUも成長・衰退・年齢処理

オフシーズン処理を全6クラブに適用し、全選手の年齢+1、成長、衰退、35歳引退、契約残年数減少を行う。

## 17. CPU契約更新

CPUも契約満了選手の更新・放出を判断する。判断材料は年齢、Overall、ポジション需要、今季成績、更新費、資金、ロスター人数。`hiddenGrowth` の直接参照は禁止する。

## 18. CPU放出

高齢、能力が低い、同ポジション過多、更新費が高い、出場が少ない選手は放出候補になりやすい。ただし最低5人、GK最低1人を維持する。

## 19. 資金サイクル修正

毎シーズン終了時に順位賞金（1位+10pt、2位+5pt）と年間基本資金+100ptを全クラブに適用する。持越し上限は150pt。

## 20. Season 2以降の補強フロー確認

毎年、育成 → 成長・衰退 → 契約 → ドラフト → 競売 → 編成 → 戦術 → シーズンを必ず実行し、人間クラブだけでなくCPUクラブも同じ年度処理に参加する。

## 21. Season 1ドラフト完全同時指名

Season 1全4巡で、人間＋CPU5クラブの計6クラブが同時指名する。同一候補に複数クラブが来た場合のみ抽選し、外れクラブは再指名する。全クラブが獲得または辞退するまで繰り返す。

## 22. ドラフト候補画面の改善

名前、年齢、ポジション、総合ランク、シュート、走力、守備、ドリブル、パス、GK、特殊能力、スカウトコメントを表示する。内部能力値は表示しない。

## 23. 競売候補画面の改善

名前、年齢、国籍、ポジション、総合、能力ランク、特殊能力、スカウトコメントを表示する。

## 24. 編成画面の能力確認性を上げる

選手一覧を見ながら、総合、シュート、走力、守備、ドリブル、パス、GK、特殊能力を比較できるようにする。カードを開かないと能力が見えない設計は禁止する。

## 25. 日本語ラベル維持

タイトル `FOOTBALL LEAGUE` 以外の主要UIは日本語中心とし、英語のみのボタンを新規追加しない。

## 26. UI上の優先情報

ドラフト・競売・編成では、年齢、能力、特能、ポジション、成長ヒントを常時表示し、「その選手を取る/使う理由」を一目で判断できるようにする。

## 27. 過度な完全情報化は禁止

`hiddenGrowth` の数値は表示せず、スカウトコメントによるヒントだけを表示する。選手育成の不確実性を残す。

## 30. 完成条件

ドラフトで候補能力を確認 → スカウトコメントから成長傾向を推測 → 特殊能力も確認 → 自クラブの所属選手と比較 → 指名/競売判断 → 編成で能力比較 → シーズン実行 → 成績確認 → 育成2人選択 → 選手ごとの成長個性が反映 → CPUクラブも同様に世代交代 → 10シーズン自然に進行、が成立すること。

## 31. 最終意図

FOOTBALL LEAGUEでは「現在強い選手」だけでなく、「伸びそうな選手」「特能が戦術に合う選手」「年齢的に育てる価値がある選手」を見極める楽しさを重要視する。

能力、特能、年齢、スカウトコメント、育成の5つが、ドラフト・競売・編成判断にしっかり意味を持つようにする。
